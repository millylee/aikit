# Web UI Daemon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an embedded Web UI served by a background daemon for managing providers, API keys, models, targets, and apply/import/update flows, controlled via `aikit daemon start|stop|restart|status`.

**Architecture:** Keep `aikit-core` as the single source of truth for config ops, import, target writers, and update checks. Add an `aikit-daemon` library crate (axum server, lifecycle, token auth, embedded assets); the existing `aikit` binary (owned by `aikit-tui`) dispatches between TUI (no subcommand) and daemon subcommands via clap. One binary, one distribution artifact.

**Tech Stack:** Rust stable, clap (derive), axum 0.8 (hyper 1.x, same ecosystem as reqwest 0.12), tokio, serde/serde_json, rand for token generation, `include_str!` for embedded UI assets (vanilla HTML/CSS/JS, no build chain, no runtime CDN).

## Global Constraints

- Single `aikit` binary; no new distribution artifacts; install scripts unchanged.
- No subcommand launches the TUI exactly as today (backwards compatible); `--version` keeps working.
- `aikit-core` owns all business logic; daemon and TUI are sibling front ends.
- Web UI is Chinese; vanilla JS only, all assets embedded in the binary, zero external runtime requests (company-network friendly).
- Default bind `127.0.0.1:7654`; override via `--port`/`--bind`; any non-loopback bind requires token auth (token is always on).
- Token: random 32-byte hex generated by `daemon start`, stored `~/.aikit/daemon.token` (owner-only), required on all `/api/*` routes and UI login; UI stores it in localStorage.
- Runtime state in `~/.aikit/daemon.json` (pid, port, token path; owner-only); stale state must be detected via HTTP probe before reuse.
- API responses never return plaintext API key values; mask like the TUI (`mask_secret`); create/replace key values via dedicated endpoints.
- Concurrency with TUI: each API mutation is a full read-modify-write of `~/.aikit/config.toml` + sidecars; last-writer-wins for Phase 1 (documented limitation).
- Reuse existing core paths verbatim: `config_ops` CRUD, `import` scan/apply, `write_target` + backup flow, model refresh, redirect-based update check (`LATEST_RELEASE_URL` pattern). No GitHub API usage anywhere.

## Tasks

### Phase 1 — CLI skeleton, serve, status, stop, token middleware

- [x] Add `clap` derive CLI in `aikit-tui/src/main.rs`: no subcommand → TUI; `daemon {start|stop|restart|status|serve}` with `--port` (default 7654) and `--bind` (default 127.0.0.1).
- [x] `aikit-daemon` crate skeleton with axum router: `GET /` (embedded placeholder page), `GET /api/health` returning version + uptime.
- [x] `token.rs`: generate on start, persist owner-only, axum middleware rejecting `/api/*` without `Authorization: Bearer <token>` (health stays open for probing).
- [x] `daemon.json` write on serve startup (pid, port); `status` reads it, HTTP-probes health, prints 运行中/已停止 + port + version; `stop` terminates by pid (Unix SIGTERM / Windows taskkill), removes daemon.json, idempotent when not running.

### Phase 2 — start / restart with detach and single instance

- [x] `start`: refuse when a live daemon answers probe; spawn `aikit daemon serve` detached (Windows `CREATE_DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`, Unix setsid), poll health until ready, print URL + token file path.
- [x] Handle stale daemon.json (pid dead, port closed) by reclaiming.
- [x] `restart`: stop (tolerate not-running) then start.

### Phase 3 — read APIs

- [ ] `GET /api/config`: full config with masked key values, targets, toggles, active selection.
- [ ] `GET /api/providers`, `GET /api/providers/:id` (with masked keys + cached models).

### Phase 4 — write APIs

- [ ] Provider CRUD: `POST /api/providers`, `PUT /api/providers/:id`, `DELETE /api/providers/:id` (validate via `ProviderForm`).
- [ ] Key endpoints: `POST .../keys` (create with plaintext value, stored), `PUT .../keys/:id`, `DELETE .../keys/:id`.
- [ ] `PUT /api/selection` (active provider/key/model), `PUT /api/targets` (enabled flags + `bypass_permissions`), `POST /api/apply` (writes enabled targets with backup, returns per-target results).
- [ ] `POST /api/import/scan`, `POST /api/import/apply` (reuse core import).
- [ ] `POST /api/models/refresh`, `POST /api/updates/check`.
- [ ] Every mutation persists via `save_with_sidecars`.
